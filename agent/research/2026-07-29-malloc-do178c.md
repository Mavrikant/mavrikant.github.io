# Araştırma notları — DAL A'da malloc "yasağı" efsanesi

## Doğrulanmış olgular
- DO-178C ana belge dinamik bellek ayırma için **açık bir yasak** içermez. Yasak gibi görünen kısıtlar, "bounded execution time", "verify robustness" ve DO-332'nin dinamik bellek objektiflerinden doğar.
- **DO-332/ED-217** (OOP + related techniques supplement, 2011) Table A-7'de dinamik bellek için iki ilave DAL A/B objektifi ekler: (a) local type consistency, (b) dynamic memory management robustness.
- DO-332 yedi endişeyi (concerns / vulnerabilities) enumerate eder:
  1. Ambiguous reference (aynı adres birden fazla değişkene işaret ediyor)
  2. Fragmentation starvation (toplam boş bellek yeter ama sürekli blok bulunamaz)
  3. Deallocation starvation (bellek serbest bırakılamıyor — canlı obje)
  4. Heap memory exhaustion (worst-case bellek talebi > heap)
  5. Premature deallocation (kullanımda olan bellek serbest)
  6. Lost update / stale reference (aynı bellek yeniden kullanılırken referans kaldı)
  7. Unbounded allocation/deallocation time (allocator WCET sınırsız)
- **TLSF** (Two-Level Segregated Fit), Masmano, Ripoll, Crespo, Real, ECRTS 2004: O(1) worst-case; iki seviyeli bitmap (FL power-of-2, SL linear subdivide); tek ffs/clz instruction ile ilk bit bulma.
- TLSF fragmentation bound (paper Section 3): worst-case internal frag = `(size << 1) / SLLEN`. Örnek 32-bit, SLLEN=32: her blok için worst-case ~%3.125.
- TLSF measured (ECRTS 2004 paper, x86 P4): <200 processor instructions worst case; deallocation benzer.
- ffs (find first set) → x86: `bsf`/`tzcnt`; ARM: `clz` + hesap veya `rbit + clz`; her ikisi de tek çevrimlik.

## Kritik ayrım
- "malloc yasak" ifadesi kısayoldur. Gerçek gereksinim: **allocator davranışını bounded ve verify edilebilir hâle getir**. Bunu sağlayan herhangi bir allocator (pool, arena, TLSF, static) prensipte kabul edilebilir; ama analiz yükü büyür.
- **Static allocation** en kolay yol çünkü yukarıdaki 7 endişenin çoğu triviyal olarak "yok" hâline gelir.
- **Pool allocator** ikinci en kolay: sabit boyutlu bloklar → internal frag hesabı statik, external frag yok, alloc/free O(1).
- **TLSF** karmaşık ama gerçekten dinamik ihtiyaç varsa (örn. RTOS'un IPC bufferı, network stack) tek gerçek DAL A/B seçenek.

## Alan doğrulama
- Wind River VxWorks 653, GHS INTEGRITY-178 tuMP, LynxOS-178: kernelde malloc yok; user partition'lara sınırlı pool sağlar.
- NASA JPL "Rules for Developing Safety-Critical Code" (Holzmann, 2006): Rule 3 → "Do not use dynamic memory allocation after initialization."
- ARINC 653'de bellek partition boundary'de belirlenir; runtime ayırma partition içi ve genelde compile-time budget'a bağlı.
